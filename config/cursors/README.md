# Cursor themes

The Firefox container shows the viewer's own native mouse cursors (for example
the current macOS arrow, I-beam and pointing hand) instead of images of Linux
cursors. It works in three parts:

1. `native-css/` is an Xcursor theme (`XCURSOR_THEME=native-css`) in which every
   cursor is a 1-pixel-tall marker image spelling a CSS cursor keyword
   (`default`, `text`, `pointer`, `ew-resize`, ...). Firefox requests cursors by
   their CSS names, so each request resolves to the matching marker.
2. The VNC server sends the marker to the browser like any cursor image.
3. The patched noVNC client (`config/novnc/cursor.js` and `cursor-keyword.js`)
   recognizes the marker and sets that CSS keyword on the page, so the viewer's
   browser draws its own native cursor.

Cursors that are not markers, such as custom cursor images on web pages, are
shown as images as before.

The theme has a file for every CSS cursor keyword and inherits from no other
theme. If a program asks for a name it lacks, GTK tries a legacy name and then
`left_ptr`, which is a marker for `default`, so the viewer sees its native
arrow. The exception is a legacy name that exists in the X core cursor font
(such as `crosshair`), which shows that 1-bit glyph instead.

Only the patched noVNC served by this container decodes markers. Any other VNC
client would draw a marker as a 1-pixel line; the compose file publishes only
the web UI port (5800), not the VNC port.

## Openbox's own cursors

The window manager, Openbox, sets some cursors itself: while it moves or
resizes a window, and over the title bars and edges of windows it decorates.
This Openbox build has no cursor-theme support, so those are 1-bit core
glyphs. For the main Firefox window, two settings keep Openbox from ever
starting a move or resize:

- `config/firefox-chrome/userChrome.css` turns off Firefox's window dragging
  from empty toolbar and tab-strip space.
- `config/firefox-init.d/58-openbox-no-alt-drag.sh` removes Openbox's Alt+drag
  move and resize bindings (Alt+Right drag also unmaximized Firefox).

Openbox's remaining cursors (the title bars, edges and title-bar drags of
windows it decorates, such as the Library or a Save As dialog, and the
desktop cursor while Firefox starts) are recognized by their exact images
instead. Openbox uses 11 fixed glyphs. `config/novnc/core-glyphs.js` holds
each one as the VNC server sends it, with the CSS keyword it stands for
(`fleur` is `move`, `left_ptr` is `default`, `bottom_side` is `ns-resize`, and
so on; edges and corners use the two-way resize cursors, because Openbox
resizes them both ways), and the patched noVNC shows the native cursor when an incoming
cursor matches one exactly (same size, hotspot and pixels).

`config/novnc/core-glyphs/capture.sh` generates that table from the image
pinned in `docker-compose.yml`: it grabs the pointer with each glyph inside a
throwaway container and reads the cursor through the VNC server.

## native-css

Generated by `generate_native_theme.py`; do not edit the files by hand. After
changing the keyword or alias tables, regenerate and run the tests:

```bash
python3 config/cursors/generate_native_theme.py
python3 -m unittest discover -s tests
node --test tests/
```

The marker format is documented in `generate_native_theme.py` and
`config/novnc/cursor-keyword.js`. The keyword list in both files must match (a
unit test checks this).

## Upgrading the Firefox image

The image tag is pinned in `docker-compose.yml`. Before changing it, regenerate
Openbox's glyph table and run both integration tests against the new tag. They
read the image from `docker-compose.yml`, so change the tag first:

```bash
config/novnc/core-glyphs/capture.sh   # then `git diff config/novnc/core-glyphs.js`
tests/e2e/run.sh       # real Firefox + VNC server: markers, prefs, Openbox drags and glyphs
tests/browser/run.sh   # the image's noVNC with the patch, in headless Chrome and Firefox
```

### The patched cursor.js

The firefox service mounts `config/novnc/cursor.js` over the image's
`/opt/noVNC/core/util/cursor.js`, so it would hide whatever a new image changed
in that file. Three files record how the overlay was made:

- `config/novnc/cursor.js.upstream.sha256`: the checksum of the image's file
  (noVNC v1.6.0's and v1.7.0's, unchanged; jlesage/firefox v26.09.1 ships it).
- `config/novnc/cursor.js.patch`: the change, as `diff -u` output. It adds the
  `nativeCursorKeyword` import from `cursor-keyword.js` and the keyword check at
  the top of `Cursor.change()`, and removes nothing.
- `config/novnc/cursor.js`: the image's file plus the patch.

`tests/browser/run.sh` and `tests/e2e/run.sh` copy the image's own file out of a
container that is never started (no mount covers it) and stop with a `FAIL`
line if its checksum is not the recorded one, or if the patch does not turn it
into `config/novnc/cursor.js` exactly (`tests/novnc_cursor_patch.py`). The unit
tests check the second part without the image: taking the patch back out of
`config/novnc/cursor.js` must give a file with the recorded checksum. So
`config/novnc/cursor.js` cannot be edited without updating the patch.

If the new image's `cursor.js` changed, re-apply the patch to it, review the
result, and record the new file. From the repository root, after changing the
image in `docker-compose.yml`:

```bash
IMAGE=$(docker compose config --format json | python3 -I -c \
    'import json, sys; print(json.load(sys.stdin)["services"]["firefox"]["image"])')
dir=$(mktemp -d)
container=$(docker create "$IMAGE")
docker cp "$container:/opt/noVNC/core/util/cursor.js" "$dir/cursor.js"
docker rm "$container"
# What upstream changed: the old file is the overlay with the patch taken back out.
patch -R -s -o "$dir/old-cursor.js" config/novnc/cursor.js config/novnc/cursor.js.patch
diff -u "$dir/old-cursor.js" "$dir/cursor.js"
patch -o config/novnc/cursor.js "$dir/cursor.js" config/novnc/cursor.js.patch
# Resolve any rejected hunk by hand in config/novnc/cursor.js, then record both files:
diff -u --label a/core/util/cursor.js --label b/core/util/cursor.js \
    "$dir/cursor.js" config/novnc/cursor.js > config/novnc/cursor.js.patch
printf '%s  core/util/cursor.js\n' "$(shasum -a 256 < "$dir/cursor.js" | cut -d' ' -f1)" \
    > config/novnc/cursor.js.upstream.sha256
python3 -m unittest discover -s tests && tests/browser/run.sh && tests/e2e/run.sh
```

(`diff` exits 1 when the files differ, which they do.) noVNC is licensed under
the Mozilla Public License 2.0: `config/novnc/cursor.js` and its patch stay
under it, as the file's header says.
